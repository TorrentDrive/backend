# Continuous SemVer Release Pipeline on Main Without Release PRs

`backend`, `frontend`, `deploy`, and `website` compute Semantic Versions from Conventional Commits, tag multi-architecture container images, update version and changelog manifests (`Directory.Build.props`, `package.json`, `VERSION`, `components.lock.json`, `CHANGELOG.md`), and publish GitHub Releases directly within the primary `main` workflow run (`[skip ci]`), rather than delegating release creation to `release-please` pull requests or bot-opened lockfile pull requests. In GitHub Actions, pull requests and git tags created with `GITHUB_TOKEN` do not trigger downstream `pull_request` or `push: tags` workflows, which previously caused automated PR checks to stall in `action_required`, forced double container builds on every release merge, and required manual human merges across three repositories to ship a single change. Documentation-only commits (`docs:` or `*.md`-only diffs) in `backend`, `frontend`, and `deploy` run fast validation only and skip container image builds and SemVer releases, while upstream component releases forward their SemVer `bump` level (`major`, `minor`, `patch`) in the `build-combined` dispatch payload so the combined release in `deploy` accurately reflects the upstream change.
